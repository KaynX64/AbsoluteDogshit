# Migration catalog and client cutovers

Follow the [migration rollout and recovery guide](MIGRATION-PLAN.md) before applying these upgrades. Audit-chain migration 016 and legacy responder migration adoption are documented there.

- Migration 004 adds the appointment status and date index for queue reads. Rehearse its DDL on a staging copy with representative appointment volume.
- Migration 005 adds indexes for prescription issue dates and inventory movement dates. The pharmacy dashboard uses them for the rolling activity window.
- Migration 006 adds the View incident records permission to the catalog. Limited Admins receive archive access when a Super Admin grants it. Legacy full-access admins and explicit Super Admins continue to pass the archive gate.
- Migration 007 adds Operations, Clinical, Pharmacy, Headcount, and Export analytics permissions. Existing Limited Admins with View analytics receive Headcount once. Super Admins can grant additional analytics access in account settings. Deploy the server and desktop together because the analytics summary now returns scoped blocks.
- The clinical and pharmacy workflow refinement uses the existing grants. Surveillance and Dispensing are derived scopes. Deploy the server and desktop together for the nested summary changes. This refinement adds no migration.
- Migration 008 creates the staff analytics settings table. It leaves the table empty so nurses, doctors and dentists inherit their existing defaults. Apply migration 008 before serving analytics with the updated server.
- Migration 009 adds nullable PDF retry timestamps and pending-PDF indexes to prescriptions, clearances and incident reports. It leaves stored PDF keys intact. Allow the startup migration to finish before serving traffic with the updated server.
- Migration 010 adds the Terminal permission to the admin catalog. Existing grants carry forward. A Super Admin can opt Limited Admin accounts into diagnostics.
- Migration 011 rebuilds `LOCAL_SYNC_LOGS` when upgrading older schemas to remove submitted payloads and free-form errors. Mutation IDs, owners, statuses, and resulting record IDs carry forward. Rehearse the table copy and account for locks and disk space. Bring the updated server up before the updated desktop so legacy ownership checks and bounded replay are available. Historical database backups, replicas and logs follow their own retention policies.
- Migration 012 adds a unique installation ID and SOS mode to device tokens and a nullable location label to emergency alerts. Apply it before deploying the Android responder update. Legacy registrations keep their existing SOS channel.
- Migration 013 adds structured prescription snapshots, ordered encrypted item details, decimal external quantities and issuance request uniqueness. Historical clinical values and stored PDFs are retained. Deploy updated server/readers with v2 issuance disabled, release desktop/mobile, complete clinician review, then enable the flag. See [prescribing rollout](../workflows/PRESCRIBING-ROLLOUT.md) and [API contract](../workflows/STRUCTURED-PRESCRIBING.md).
- Migration 014 adds account-scoped SOS request identities and a delivery lease to `EMERGENCY_ALERTS`. Existing alerts have no scheduled delivery. Deploy the API and confirm the SOS Dispatch Worker is running before releasing the keyed mobile client. Test an interrupted receipt and a concurrent retry against disposable MySQL.
- Migration 015 adds encrypted author-owned incident report drafts and history indexes. The pending worklist keeps unfinished reports across days. [Responder records and client rollout](../workflows/RESPONDER-RECORDS.md).
- Migration 017 adds responder applications, reviewers, assessments, private evidence, appointments and notices. Existing roles/flags become draft candidates, never approvals. Preserve staged legacy access while clinic reviewers prepare a roster, deploy clients, then explicitly enable qualification enforcement. Fresh schemas include labelled synthetic demos; existing production migrations do not fabricate approval. See [qualification deployment](../workflows/RESPONDER-QUALIFICATIONS.md#deployment-and-synthetic-scenarios).
